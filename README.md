# Система управления ритуальными услугами ООО «Боже»

Учебный проект для простого и понятного оформления и обработки заявок на ритуальные услуги.

Сейчас backend поддерживает:

- регистрацию и изменение клиентов;
- создание и ведение заявок на погребение или кремацию;
- проверку даты церемонии, стоимости и допустимых переходов статуса;
- поиск, фильтрацию и сортировку заявок;
- экспорт заявок в XLSX.

В дальнейшем предметную область можно расширить каталогом услуг: выбором религии или атеизма,
свободными датами отпевания, редактором памятника, организацией поминального стола и заказом ведущего.

## Запуск

Для локального запуска нужна Java 21 или новее:

```bash
mvn -pl backend spring-boot:run
```

В другом терминале запустите консольный клиент:

```bash
mvn -pl console-client package
java -jar console-client/target/console-client-1.0-SNAPSHOT.jar
```

Клиент показывает главное меню и после каждого действия возвращается в него или в текущий
раздел. Доступны добавление, просмотр, изменение и удаление клиентов и заявок, поиск,
фильтрация, простая статистика и экспорт в `funeral-requests.xlsx`. Для подключения к
серверу на другом адресе задайте `FUNERAL_API_URL`, например
`FUNERAL_API_URL=http://localhost:8081`. Сначала запустите backend.

По умолчанию используется встроенная файловая база H2. Данные сохраняются в файле
`funeral-agency.mv.db` в каталоге запуска backend и остаются после перезапуска.
Чтобы создать заявку, сначала добавьте клиента и выберите его ID из показанного списка.
Внешнюю базу можно подключить переменными
`DB_URL`, `DB_USERNAME`, `DB_PASSWORD` и `DB_DRIVER`.
Для PostgreSQL, например: `DB_URL=jdbc:postgresql://localhost:5432/funeral_agency`,
`DB_USERNAME=postgres`, `DB_PASSWORD=...`, `DB_DRIVER=org.postgresql.Driver`.

Основные REST-маршруты:

- `/api/clients` — клиенты;
- `/api/funeral-requests` — заявки;
- `/api/funeral-requests/search?query=...` — поиск;
- `/api/funeral-requests/filter` — фильтрация;
- `/api/funeral-requests/sort` — сортировка;
- `/api/funeral-requests/export` — экспорт в XLSX.

Ошибки API возвращаются в едином JSON-формате с полями `timestamp`, `status`, `error`,
`message` и `path`. Клиента со связанными заявками удалить нельзя: API возвращает
`409 Conflict`, сохраняя клиента и историю его заявок.

## Проверка

```bash
mvn test
bash scripts/full-scenario-test.sh
```

Второй тест запускает отдельный backend и CLI на временной базе, проходит создание,
просмотр, изменение, поиск, фильтрацию, экспорт и удаление, затем проверяет данные после
перезапуска сервера. Работающий экземпляр приложения он не меняет.
